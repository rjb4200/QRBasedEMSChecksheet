# n8n Alert Workflow Setup Guide

This guide configures n8n to send the daily EMS checkoff alert email at 09:00 Eastern time.

The workflow calls the app API, checks whether an alert should be sent, and emails the generated alert content plus a link to the daily printable check sheets.

## Requirements

- A deployed app URL, for example `https://your-app-domain.com`
- An n8n instance that can reach the deployed app URL
- SMTP credentials for the account that will send the alert email
- Recipient email address or distribution list for admins

The n8n workflow does not need Supabase credentials. It only calls the app endpoint:

```text
GET https://your-app-domain.com/api/alerts/incomplete-units
```

## What The App Endpoint Returns

The endpoint returns JSON similar to this:

```json
{
  "shiftDate": "2026-04-30",
  "shiftPeriod": "daily",
  "shouldSend": true,
  "incompleteUnits": [],
  "discrepancies": [],
  "checkSheets": {
    "date": "2026-04-30",
    "printUrl": "https://your-app-domain.com/admin/checksheets/print?date=2026-04-30"
  },
  "email": {
    "subject": "EMS Checkoff Alert: 1 incomplete unit, 2 exceptions",
    "text": "Incomplete in-service units:\n\nEC5: 29 of 30 checks completed (96.67%)\n..."
  }
}
```

Important fields:

- `shouldSend`: `true` means send the email.
- `email.subject`: subject line for the alert email.
- `email.text`: plain-text body generated by the app.
- `checkSheets.printUrl`: printable daily check sheet URL for the alert date.

## Workflow Overview

Create this n8n workflow:

1. `Schedule Trigger`
2. `HTTP Request`
3. `IF`
4. `Send Email` on the `true` branch

## Step 1: Create The Workflow

1. Open n8n.
2. Select `New Workflow`.
3. Name it:

```text
EMS Daily Checkoff Alert
```

## Step 2: Add Schedule Trigger

Add a `Schedule Trigger` node.

Recommended settings:

- Trigger interval: `Days`
- Every: `1`
- Time: `09:00`
- Timezone: `America/New_York`

If your n8n version uses cron expression mode, use:

```text
0 9 * * *
```

Make sure the workflow or n8n instance timezone is set to `America/New_York`, otherwise the alert may run at 09:00 UTC instead of 09:00 Eastern.

## Step 3: Add HTTP Request Node

Add an `HTTP Request` node after the schedule trigger.

Settings:

- Method: `GET`
- URL:

```text
https://your-app-domain.com/api/alerts/incomplete-units
```

- Authentication: `None`
- Response format: `JSON`

Replace `https://your-app-domain.com` with the deployed app domain.

Example:

```text
https://qrbasedemschecksheet.example.com/api/alerts/incomplete-units
```

## Step 4: Test The HTTP Request

Run the `HTTP Request` node manually.

Expected result:

- The node succeeds with status `200`.
- The output contains `shouldSend`.
- The output contains `email` when `shouldSend` is `true`.
- The output contains `checkSheets.printUrl`.

If `shouldSend` is `false`, the workflow is still working. It means all units are complete and no submitted missing/below-par exceptions currently exist.

## Step 5: Add IF Node

Add an `IF` node after the HTTP Request node.

Condition:

- Value 1:

```text
{{$json.shouldSend}}
```

- Operation: `is true`

Only the `true` branch should send email.

Leave the `false` branch empty, or optionally connect it to a `No Operation` node.

## Step 6: Configure SMTP Credentials

In n8n, create SMTP credentials for the sending account.

Common SMTP fields:

- Host: your SMTP server hostname
- Port: usually `587` for STARTTLS or `465` for SSL
- User: SMTP username
- Password: SMTP password or app password
- SSL/TLS: match your provider requirements

Examples:

- Google Workspace usually requires an app password or SMTP relay configuration.
- Microsoft 365 may require authenticated SMTP to be enabled for the mailbox.
- Self-hosted SMTP should use TLS when possible.

## Step 7: Add Send Email Node

On the `true` branch from the IF node, add a `Send Email` node.

Settings:

- Credentials: select the SMTP credentials created above
- From Email: the sender email address
- To Email: admin recipient or distribution list
- Subject:

```text
{{$json.email.subject}}
```

- Email Format: `Text`
- Text:

```text
{{$json.email.text}}

Daily check sheets:
{{$json.checkSheets.printUrl}}
```

Optional CC/BCC:

- Add supervisor or admin distribution lists if required.

## Step 8: Optional HTML Email

If you prefer HTML email, use this body:

```html
<pre>{{$json.email.text}}</pre>

<p>
  <strong>Daily check sheets:</strong><br>
  <a href="{{$json.checkSheets.printUrl}}">Open printable daily check sheets</a>
</p>
```

Use plain text first. Switch to HTML only after the workflow is verified.

## Step 9: Activate The Workflow

After testing:

1. Save the workflow.
2. Toggle `Active` on.
3. Confirm n8n shows the next scheduled run time.

## Testing Checklist

Use this checklist before relying on the workflow:

- Run the HTTP Request node manually.
- Confirm the response has `shouldSend`.
- Temporarily force an incomplete unit or submitted exception in the app.
- Run the full workflow manually.
- Confirm the IF node follows the `true` branch when `shouldSend` is `true`.
- Confirm the email arrives.
- Click the `Daily check sheets` link in the email.
- Confirm the print page opens for the correct date.
- Confirm no email is sent when `shouldSend` is `false`.

## Troubleshooting

### HTTP Request Fails

Check:

- The deployed app URL is correct.
- The app is online.
- n8n can reach public internet or the app network.
- The endpoint path is exactly `/api/alerts/incomplete-units`.

### Email Does Not Send

Check:

- SMTP credentials are valid.
- SMTP port and TLS settings match the provider.
- The sender account allows SMTP.
- The recipient address is valid.
- The IF node is on the `true` branch.

### Workflow Runs At Wrong Time

Check:

- Schedule node timezone is `America/New_York`.
- n8n instance timezone is not overriding the workflow timezone.
- Cron expression is `0 9 * * *` if using cron mode.

### No Email Is Sent But Workflow Succeeds

Check the HTTP response:

```text
{{$json.shouldSend}}
```

If it is `false`, the app found no incomplete in-service units and no submitted missing/below-par exceptions.

### Check Sheet Link Opens Login Or Fails

The check sheet print route is under `/admin/checksheets/print`. If the deployed app protects admin routes, open the link while signed in as admin.

If the link must be opened by non-admin recipients, a future change should add a signed public print token route.

## Current App Behavior

The alert is sent when either condition is true:

- Any in-service unit is under 100% complete.
- Any submitted item exception exists for the alert day.

Completion includes:

- Completed compartments.
- Locked crew/provider names.

Exceptions include:

- Checkbox items submitted as missing.
- Quantity items submitted below configured par.

Soft-deleted units are excluded from current alerts.

## Recommended Workflow Node Names

Use these names so the workflow is easy to maintain:

- `Daily 09:00 Trigger`
- `Get Checkoff Alert Payload`
- `Should Send Alert?`
- `Email Admin Alert`
